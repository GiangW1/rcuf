# RTX 5090 两卡先导实验（2026-10-16）

**投影恢复即时有效，但本轮未通过持续性门槛。以下标签来自 Codex 模型语义复核，正式人工盲审尚未完成。**

Qwen3.5-4B 在 32K 英文资料后的法语策略明显漂移；即时投影恢复、低秩相加和文字提醒均恢复至 32/32 联合成功。投影恢复在继续读取 4096 token 后降至 11/32，同条件低秩相加仍为 32/32。这轮结果不支持投影恢复优于相加，也没有达到“一次恢复在 4096 token 后保留至少一半即时收益”的预设门槛。

## 主要结果

联合成功要求**回答为法语，且目标项目的授权码和预算均正确**。每个测试条件使用相同的 32 篇独立测试文档。

| 方法 | 即时，32K | 延迟 512 token | 延迟 4096 token |
|---|---:|---:|---:|
| 未干预基线 | 0/32 | 0/32 | 0/32 |
| 全秩相加 | 32/32 | 未测试 | 未测试 |
| 低秩相加 | 32/32 | 32/32 | 32/32 |
| 投影恢复 | 32/32 | 31/32 | 11/32 |
| 文字提醒 | 32/32 | 未测试 | 未测试 |
| 英语错误锚点 | 0/32 | 未测试 | 未测试 |

所有上述测试条件的内容正确率均为 32/32。短输入基线语言和内容均为 32/32；8K 基线法语遵循为 1/32，内容为 32/32。开发集的 160 条回答中有 2 条授权码错误，已计入失败。

4096-token 投影恢复相对同延迟未干预基线的联合净增为 11/32，保留即时净增 32/32 的 **34.4%**，小于预设 50%。相对同延迟低秩相加，配对差为 −21/32（−65.6 个百分点），文档级 bootstrap 95% CI 为 [−81.25, −50.0] 个百分点。该区间描述当前样本；本轮不作机制或跨任务的泛化结论。

## 配置、数量与实际成本

- 模型：`Qwen/Qwen3.5-4B`，revision `851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a`。
- Python 3.11.17；torch 2.8.0+cu128；transformers 5.19.0；FLA 0.5.2；SDPA；BF16；CPU 缓存快照；2048-token 预填分块。
- 8 篇开发文档、32 篇测试文档；参考长度 0/8192/32768；rank=4；每次最多生成 128 token。
- 只用开发集选择强度，冻结结果：`add_full=1.0, add_lowrank=1.0, replace=1.0`。测试集未用于重新调参。
- 两张 RTX 5090，每张独立加载一份模型，按文档分片。baseline 使用物理 GPU 6/7；后续因占用变化改用 5/6，分片不变。服务器与其他任务共享，耗时不作为独占卡基准。

| 阶段 | 结果行数 | 新生成回答数 | 较慢 worker 的实测时间 |
|---|---:|---:|---:|
| baseline | 96 | 96 | 146.3 秒 |
| tune（开发集） | 160 | 160 | 254.9 秒 |
| compare | 384 | 320（64 条复用基线） | 314.6 秒 |
| delay | 192 | 192 | 254.1 秒 |
| 合计 | 832 | **768** | 约 **16 分 10 秒** |

时间包含 worker 加载、参考状态、运行时检查、预填和分支生成，不含阶段间复核；两卡时间使用每阶段较慢 worker，而非把两卡秒数相加。smoke 的 6 条回答另存，不计入以上实验统计。

## 审阅方式与协议偏离

原仓库协议要求所有回答经人工盲审才能判定最终关卡。这次为自主推进探索，以 **Codex 模型语义复核替代人工审核**，原始空白盲审导出保留于 `artifacts/*-review.jsonl`；模型标签独立保存在 `*-model-review.jsonl`，每行明确标记 `human_reviewed=false`。

导出隐藏方法、强度、长度和自动标签。复核时仅将每行正确的预期项目/授权码/预算的精确出现替换为占位符，再按完全相同的回答模板分组阅读，错误值和其他文本保留；开发、对比、延迟分别有 37/50/29 个模板，决策及其覆盖的 review IDs 见 `audit/*-template-audit.json`。未直接复制生成器的自动评分。协调者知道实验设计并看过基线汇总，**不构成独立人工盲审**。

汇总中的 `review_complete=true`、`continue_pilot` 是这次替代复核流程的机器字段；额外的 `human_review_complete=false` 和 `reviewer_type` 标明其限制。不能将这些字段解读为完成了原协议的人工盲审。默认仓库的人工审核要求和关卡阈值均未改动。

## BF16 检查调整

原始短缓存检查在 5090 上因 BF16 分块数值误差未通过。先做 BF16/FP32、FLA/PyTorch 参考实现诊断，再在正式 baseline 前调整检查：BF16 的逐 logit `atol` 从 0.15 改为 0.25，`rtol=0.02` 不变；额外要求 `KL(full || continued) <= 0.01`，并保持相同贪心首 token、独立缓存分叉复现和状态干预有效性检查。FP32 的绝对容差保持 0.15。

FP32/PyTorch 参考续接的最大 logits 差为 4.10e-5；诊断数据见 [数值调整说明](audit/bf16-adjustment.md) 和 [完整诊断统计](audit/cache-diagnostics/report.json)。本次代码补丁与实际运行的源码指纹一致；没有根据实验收益事后改变生成或关卡逻辑。

## 文件与校验

- `artifacts/`：原始输出、token、自动标签、复核标签、scored rows、冻结选择、逐 worker 运行时/缓存检查/成本和汇总。JSON/JSONL 字节与服务器归档相同。
- `audit/`：模型与数据来源校验、环境版本、数值诊断、审阅来源和模板决策、CPU/GPU 检查记录；保留模型复核前的 baseline 汇总。
- `data-manifest.json`、`config-frozen.json`：原始冻结配置和数据指纹；保留当时服务器路径以维持哈希。
- `server-report.md`：服务器生成的逐阶段完整报告，含历史本机路径。
- `SHA256SUMS`：本发布包所有其他文件的逐文件 SHA256。

在仓库根目录执行，无需模型、GPU 或第三方 Python 依赖：

```bash
python3 reports/2026-10-16-rtx5090-pilot/verify.py
```

校验发布包哈希、源码指纹、cell IDs、回答哈希、复核与原回答的绑定、逐行评分、汇总指标、选择绑定和关卡判定。不重复推理、不从原始 token 流验证输入，也不重新计算 bootstrap 区间。模型权重、Wikipedia 原文、token 流和大型 logits 张量保留在原服务器，未纳入此发布包。

## 重新运行

正式重跑请沿用根 README 的人工盲审流程，另建 data/run 目录。Blackwell/RTX 5090 需使用支持该架构的 PyTorch CUDA 12.8 wheel；本轮用 `torch==2.8.0 --index-url https://download.pytorch.org/whl/cu128`。

资料来自 `wikimedia/wikipedia` 的 `20231101.en`，固定 HF revision `b04c8d1ceb2f5cd4588862100d08de323dccfbaa` 的首个 parquet。源分片及模型文件 SHA256 在 `audit/*-verified.json`。按官方顺序取前 4000 行，逐行以 `json.dumps({key: row[key] for key in ['id', 'title', 'url', 'text']}, ensure_ascii=False) + '\n'` 导出；原导出 SHA256 为 `4691727f20e513e6269bb9b8e691fc18eb9794942b59434b5127522f99fbcce9`，再用 `rcuf prepare --corpus-jsonl ...` 过滤和冻结。

将冻结配置的 `model` 改为本机模型目录或官方模型 ID，然后在新目录准备数据。路径改动会改变配置/manifest 指纹，因此不要把新生成的样本写回本归档。原始权重和语料的许可、来源请遵循各自官方发布。
